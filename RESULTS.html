EuroSAT model-size study

How small can an accurate satellite-image classifier be?

This report explains what we have learned so far, compares the best models with a simple per-band statistics baseline, and shows how the project moved from its original main baseline to the final merged results.

Bottom line

The simple baseline misses the target. Better measurements are also smaller.

A model that sees only the mean, standard deviation, minimum, and maximum of each spectral band reaches 90.96% test accuracy. The best compact models see useful spatial patterns such as edges, line direction, boundaries, and corners. Because those measurements carry more information, the final classifier needs fewer learned numbers.

In plain English

Four numbers per band describe the overall color and spread of a patch, but they do not say where anything is. Roads, field boundaries, crop rows, and built-up areas are spatial patterns. Once the model is given compact measurements of those patterns, it becomes both more accurate and smaller.

64.2% fewer parameters

The 94% frontier uses 171 parameters instead of the baseline's 477, while improving test accuracy by 3.37 percentage points.

41.5% fewer parameters

The current 95% model uses 279 parameters instead of 477, while improving test accuracy by 4.41 percentage points.

The comparison point

What exactly is the simple baseline?

For each image patch, the baseline reduces every spectral band to four numbers. It then trains ordinary logistic regression and chooses the regularization setting, called C, that performs best on the validation set.

Meanaverage brightness
Stdevamount of variation
Minimumdarkest pixel
Maximumbrightest pixel

52 total inputs: 13 bands multiplied by 4 statistics. These measurements are fixed calculations, so the only learned numbers are in the logistic-regression classifier.

How C was chosen

The model was trained on 16,200 images for each value of C. The validation set selected C=300 at 90.93%. Only then was the final 90.96% test score calculated.

The results flatten out between about 100 and 2,000, so more tuning is not likely to close the gap to 94%.

How many parameters?

A standard 10-row classifier stores 530 values. One row is mathematically redundant, so the exact same decisions can be stored with 477 values. We use 477 for the fair comparison with the newest models.

9 class rows × (52 inputs + 1 bias) = 477

Why it falls short: The baseline knows the range and spread of each band, but it cannot tell whether bright or dark pixels form a road, a field edge, a grid of buildings, or random texture.

Results so far

The model became smaller in four stages

The first useful model already used fixed image measurements and a linear classifier. Most later progress came from making those measurements more informative and choosing a smaller set of them.

Add spatial measurements

Percentiles and multiscale gradients pushed the first submission to 95.02% test accuracy. Direction, band-to-band relationships, and vegetation-index texture then let the model keep fewer inputs.

Choose features by removing redundancy

Simple coefficient ranking needed 34 inputs for a robust 94% model. Backward selection repeatedly removed the least useful input and retrained, reducing the same pool to 25 inputs.

Add global line and corner measurements

One useful line measurement and one useful corner measurement captured structure that local texture summaries missed. They moved the 94% floor from 25 inputs to 18.

Remove a redundant class-score row

The 10 class scores can all be shifted by the same amount without changing the answer. Setting one class score to zero reduced 190 stored values to 171 with exactly the same predictions.

Important context about the 95% numbers

Submission 01 happened to score 95.02% on test, but it was selected for the original 94% task, had only 94.26% validation accuracy, and stored 1,010 parameters. Submission 13 is the meaningful 95% result because it was selected with 95.31% validation accuracy and two separate cross-validation checks around 95.7%.

A 28-input model reached exactly 95.00% validation but only 94.94% test. That is why submission 13 uses a validation target of about 95.3% instead of accepting the first result that barely touches 95%.

What worked

The useful idea was better information, not a fancier classifier

Every winning model still ends with logistic regression. The improvements came from giving that simple classifier compact measurements that match the physical structure of the classes.

Edges and texture

Mean and standard deviation reached only 87.8%. Multiscale gradients supplied the missing spatial signal and first pushed a linear model past 95%.

Direction and band relationships

Edge direction helps distinguish roads and organized crop rows from irregular texture. Comparing spatial patterns across bands helps separate vegetation, water, and built surfaces.

Texture of physical indices

NDVI and related index maps show material boundaries after reducing illumination effects. Their gradients became some of the most useful low-cost inputs.

Lines and corners

A long straight road is different from many short parallel crop edges, and a grid of intersecting streets is different again. Line and corner measurements captured those differences directly.

Backward feature selection

Two highly ranked inputs can carry almost the same information. Removing one input at a time and retraining found those redundancies better than a single ranking.

Exact parameter accounting

The feature standardizer can be absorbed into the classifier, and one class-score row is redundant. Both changes reduce storage without changing a prediction.

What did not work

Several reasonable ideas used more parameters without solving the real problem

These experiments were useful because they show where not to spend effort. The recurring problem was weak or redundant inputs, not a classifier that was too simple.

No gain

Small neural-network heads

A bottleneck network and squared feature combinations fit validation data more closely but did not improve held-out test results.

Accuracy collapsed

Fewer class-score dimensions

All nine meaningful class-separation directions are needed. Reducing below nine caused large accuracy losses.

Worse at equal size

Sparse individual weights

Selecting whole inputs lets all classes share useful information. Scattering the same budget across individual weights was about 0.8 points worse.

Too weak

Tiny convolutional models

The best single-convolution model reached only 89.2% with 2,058 parameters. Its global averaging removed too much spatial structure.

Teacher could not help

Knowledge distillation

A teacher near 98% accuracy could not overcome the small student's limited representation. Soft labels do not add model capacity.

About 17 times larger

Random convolutional features

MOSAIKS can pass 95%, but it needs roughly 4,617 classifier parameters because hundreds of generic features are needed.

The main lesson

A purpose-built measurement such as "how strong is the longest line in the vegetation map?" can summarize a useful idea in one number. Generic learned or random features need many more numbers to discover the same structure at these model sizes.

How to read the results

A few definitions and honesty checks

The project is optimizing an unusual objective: pass an accuracy threshold with as few learned numbers as possible. The definitions below explain what is counted and how model choices are made.

What is a parameter?

A parameter is a learned number that must be stored for prediction. Means, gradients, line scores, and corner scores are fixed calculations, so they do not add learned parameters.

What is validation?

Validation uses separate images to choose settings such as C or the number of inputs. The test set is held back for the final reported score.

What is cross-validation?

The training data is repeatedly split into smaller training and checking groups. Averaging those results is less noisy than relying on one split.

Why one class row can be removed without changing the model

The classifier gives every class a score and chooses the largest score. Subtracting the same value from every score does not change which one is largest. We subtract the first class's score from all 10 scores, which makes the first row exactly zero. That zero row does not need to be stored. The other nine rows produce exactly the same class decisions and the same probabilities as the original 10-row model.

Why the later feature-selection checks are stricter

A feature-selection algorithm can accidentally become good at the exact cross-validation splits that guide it. Later experiments therefore use one set of training splits to choose features, two different sets of splits to check the result, and the separate validation set as another gate. Test results do not guide the choice.

With 5,400 validation images, ordinary sample-to-sample variation is around 0.3 percentage points near these scores. That is why the 95% model aims for roughly 95.3% validation rather than accepting a result that barely reaches 95.0%.

Caveats in the historical results

Submissions 03 and 05 were selected by training-only cross-validation and passed the test threshold even though their validation scores were slightly below 94%. Later submissions use a stricter rule that also requires validation to pass.

The 252-parameter 95% result is still an experiment, not a complete raw-image submission. Submission 13 is the smallest current 95% model whose entire feature path already lives in the reusable source code.

Reproduction

Run the baseline and the two current frontier models

The HTML file has no external fonts, scripts, stylesheets, or images. It can be opened directly from disk. The commands below reproduce the measured baseline and evaluate the saved 94% and 95% models.

python experiments/image_statistics_baseline.py
python submissions/12_reference_class_linear/eval.py
python submissions/13_reference_class_95/eval.py
experiments/image_statistics_baseline.py computes the 52 image statistics, tunes C on validation, and evaluates test once.
experiments/image_statistics_baseline_result.txt stores the complete C sweep and per-class results.
submissions/12_reference_class_linear/model.npz stores the 171-parameter 94% model.
submissions/13_reference_class_95/model.npz stores the 279-parameter 95% model.
